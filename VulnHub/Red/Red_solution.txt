[17] VULNERABILITIES IDENTIFIED
================================================================================

1. PLANTED PHP WEBSHELL (Critical)
   File     : /var/www/wordpress/NetworkFileManagerPHP.php
   Impact   : LFI enabling arbitrary file read
   Fix      : File integrity monitoring; audit web root for unauthorized files

2. LOCAL FILE INCLUSION — UNSANITIZED include() (Critical)
   Code     : include($_GET['key']);
   Impact   : Read of /etc/passwd, wp-config.php, PHP source files
   Fix      : Allowlist permitted paths; disable allow_url_include in php.ini

3. CREDENTIAL REUSE — wp-config.php → SSH (High)
   Detail   : DB password (mutated) also valid for SSH login
   Fix      : Unique credentials per service; enforce SSH key-only auth

4. SUDO MISCONFIGURATION — /usr/bin/time (High)
   Entry    : (ippsec) NOPASSWD: /usr/bin/time
   Impact   : Shell as ippsec via: sudo -u ippsec /usr/bin/time /bin/bash
   Fix      : Audit sudoers; avoid NOPASSWD for GTFOBins-exploitable binaries

5. WRITABLE .git + PRIVILEGED CRONJOB (Critical)
   Detail   : /var/www/wordpress/.git writable by ippsec; root cronjob compiles C files there
   Impact   : Root privilege escalation via malicious C payload
   Fix      : Restrict .git permissions; verify cronjob privilege levels

================================================================================
[18] SECURITY RECOMMENDATIONS
================================================================================

1. SSH Hardening
   - Disable password auth: PasswordAuthentication no (in /etc/ssh/sshd_config)
   - Enforce SSH key-based authentication only
   - Deploy fail2ban to block brute-force attempts

2. PHP / Web Application
   - Disable dangerous PHP functions in php.ini:
       disable_functions = system,exec,shell_exec,passthru,proc_open,popen
       allow_url_include = Off
       allow_url_fopen = Off
   - Never pass raw user input to include() or require()
   - Implement Web Application Firewall (WAF)

3. Credential Management
   - Use unique, randomly generated passwords per service
   - Never store credentials in web-readable config files without additional protection
   - Implement secrets management (HashiCorp Vault, AWS Secrets Manager)

4. Filesystem & Cronjob Security
   - Apply principle of least privilege to all cron-monitored directories
   - Audit all crontabs: crontab -l, /etc/cron.d/, /etc/crontab
   - Implement file integrity monitoring (AIDE, Tripwire) on sensitive paths

5. Sudo Policy
   - Run regular sudo audits across all users
   - Avoid NOPASSWD for any binary listed on GTFOBins
   - Grant only specific, necessary commands with fixed arguments

6. Incident Response
   - Audit all running processes and crontabs immediately on compromise
   - Look for defense scripts in /root or hidden directories
   - Check for modified system binaries (cat, ls, etc.)
