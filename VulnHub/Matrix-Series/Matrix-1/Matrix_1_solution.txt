[10] VULNERABILITIES IDENTIFIED
================================================================================

1. SENSITIVE FILE EXPOSED ON OBSCURE PORT (High)
   Detail   : Cypher.matrix hosted on port 31337 without authentication
   Impact   : Leaks encoded credentials to any user who enumerates ports
   Fix      : Never expose credential material on public interfaces;
              require authentication on all HTTP services

2. WEAK / BRUTE-FORCEABLE PASSWORD (High)
   Detail   : Guest password k1ll0r7n falls within a 1296-entry wordlist
   Impact   : Hydra recovers it in seconds
   Fix      : Enforce strong password policy; disable SSH password auth;
              use key-based authentication only

3. RESTRICTED SHELL BYPASS VIA vi (Medium)
   Detail   : rbash with only vi in PATH; vi permits :!/bin/sh shell escape
   Impact   : Complete rbash bypass in one command
   Fix      : Do not rely on rbash for security; avoid placing GTFOBins-
              exploitable binaries in restricted PATH; use proper
              containerization or chroot instead

4. SUDO MISCONFIGURATION — (ALL) ALL (Critical)
   Detail   : guest has unrestricted sudo access to all commands
   Impact   : Trivial privilege escalation to root
   Fix      : Apply principle of least privilege; never grant (ALL) ALL
              without strong justification; audit /etc/sudoers regularly

================================================================================
[11] SECURITY RECOMMENDATIONS
================================================================================

1. SSH Hardening
   - Disable password authentication: PasswordAuthentication no
   - Enforce SSH key-based authentication only
   - Deploy fail2ban to block brute-force attempts
   - Consider port-knocking or VPN access for SSH

2. Credential & File Exposure
   - Never host files containing credentials (even encoded) on unauthenticated
     HTTP endpoints
   - Treat all encoding (base64, brainfuck, ROT13) as security theater, not
     actual security — obfuscation is not encryption

3. Restricted Shell Design
   - rbash alone is insufficient for security boundaries
   - Avoid placing GTFOBins-listed binaries (vi, less, man, awk, etc.) in
     restricted PATH — see https://gtfobins.github.io/
   - Use real sandboxing: namespaces, containers, or chroot with minimal toolsets

4. Sudo Policy
   - Audit all sudoers entries: visudo, getent passwd, sudo -l per user
   - Never assign (ALL) ALL to unprivileged accounts
   - Require re-authentication (remove NOPASSWD where not strictly needed)
   - Use specific command paths with fixed arguments
